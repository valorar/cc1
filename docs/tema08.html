1. Software de sistema y software de aplicación

En el Tema 4 dividiste el sistema informático en hardware, software y personas. Ahora toca abrir la segunda caja: el software no es un bloque único, sino capas que se apoyan unas en otras.

CapaDe qué se ocupaEjemplos
FirmwareArrancar el equipo y controlar lo más cercano al hardware.La UEFI del Tema 6
Sistema operativoAdministrar procesos, memoria, dispositivos, archivos y usuarios.Windows, GNU/Linux, macOS, Android
Bibliotecas y serviciosOfrecer funciones ya resueltas que muchas aplicaciones reutilizan.Cifrado, lectura de imágenes, dibujo de ventanas
AplicacionesResolver la tarea concreta que interesa a una persona.Navegador, editor de texto, hoja de cálculo

El software de sistema comprende las tres primeras capas: no resuelve ningún problema del usuario, sino que crea las condiciones para que otros programas puedan resolverlo. El software de aplicación es el que usas de forma consciente.

DefiniciónUn sistema operativo es el programa que administra los recursos del equipo y ofrece a las aplicaciones y a las personas una forma cómoda y segura de usarlos, ocultando los detalles del hardware.

La palabra clave es ocultar. Un procesador de textos no sabe si estás guardando en un SSD NVMe, en un disco duro o en una carpeta de red: le pide al sistema «guarda este archivo» y el sistema se ocupa. Esa abstracción hace posible que un mismo programa funcione en miles de configuraciones distintas.

💡 La clasificación no siempre es rígida. Un navegador web es una aplicación, pero también ejecuta aplicaciones web dentro de él y ofrece servicios a sus extensiones: se comporta como una plataforma. Las capas son un modelo útil, no compartimentos estancos.

2. Las cinco funciones de un sistema operativo

2.1. Gestión de procesos

Un programa es un archivo con instrucciones guardado en el disco. Cuando lo ejecutas, el sistema crea un proceso: una ejecución concreta con su propia memoria, su estado y sus recursos abiertos. Un mismo programa puede dar lugar a varios procesos a la vez —tres ventanas del navegador—, y cada proceso puede tener varios hilos trabajando en paralelo dentro de él.

Distinción observableEl programa es código almacenado; el proceso es una ejecución concreta con estado y recursos. Por eso puedes cerrar una ventana sin desinstalar la aplicación, y por eso el administrador de tareas muestra procesos, no programas.

Como hay muchos más procesos que núcleos, el planificador reparte el tiempo de CPU en porciones minúsculas y va alternando entre ellos. La sensación de que todo ocurre a la vez es una ilusión muy bien construida.

2.2. Gestión de memoria

El sistema asigna a cada proceso un espacio de memoria y, sobre todo, impide que un proceso lea o escriba en el espacio de otro. Sin esa protección, cualquier programa con un fallo podría corromper los datos de los demás, y cualquier programa malicioso podría espiarlos. Cuando la RAM se agota, entra en juego la memoria virtual que viste en el Tema 5.

2.3. Gestión de dispositivos

El sistema habla con cada periférico a través de su controlador, y ofrece a las aplicaciones una interfaz uniforme. Gracias a eso, «imprimir» significa lo mismo para el programa aunque haya cientos de modelos de impresora distintos.

2.4. Gestión de archivos

El almacenamiento físico son bloques numerados. El sistema los convierte en algo manejable: archivos con nombre organizados en carpetas, con fechas, tamaños y permisos.

2.5. Gestión de usuarios y seguridad

El sistema identifica quién está usando el equipo, guarda sus datos separados de los demás y decide qué puede hacer cada uno. Es la función que responde a la pregunta guía de este tema.

3. Componentes: núcleo, intérprete y sistema de archivos

Núcleo (kernel)

La parte central, que se ejecuta con privilegios máximos. Planifica procesos, administra la memoria, controla los dispositivos y hace cumplir la protección. Es lo primero que se carga y lo último que se descarga.

Intérprete de comandos

El programa que recibe las órdenes del usuario y las traduce en peticiones al núcleo. Puede ser una consola de texto o la propia interfaz gráfica.

Sistema de archivos

Las reglas que determinan cómo se organizan los datos en el soporte: dónde está cada archivo, cuánto ocupa, quién puede abrirlo y cómo se recupera tras un apagón.

3.1. Los sistemas de archivos más habituales

SistemaDónde se usaQué conviene saber
NTFSWindowsPermisos detallados, registro de cambios, archivos de gran tamaño.
ext4GNU/LinuxEl estándar habitual en Linux; robusto y muy probado.
APFSmacOS e iOSOptimizado para SSD, con instantáneas y cifrado integrado.
exFATMemorias USB y tarjetasLo entienden casi todos los sistemas; es la opción para intercambiar.
FAT32Dispositivos antiguosCompatibilidad máxima, pero no admite archivos de más de 4 GB.
💾 ¿Sabías que…? Ese límite de 4 GB de FAT32 es la causa de un error clásico: copiar una película o una imagen de disco a un pendrive y recibir un «no hay espacio suficiente» cuando el pendrive está prácticamente vacío. No falta espacio: el sistema de archivos no sabe representar un tamaño mayor. Se resuelve formateando en exFAT. Y el número no es casual: 4 GiB es exactamente 232 bytes, el mismo límite aritmético que viste en los buses del Tema 5.

4. Archivos y rutas: dónde está cada cosa

Los archivos se organizan en una jerarquía de carpetas en forma de árbol. Para indicar dónde está uno se usa una ruta.

RutaTipoCómo se interpreta
/home/ana/proyecto/datos.csvAbsolutaUbicación completa desde la raíz del sistema.
C:\Usuarios\ana\datos.csvAbsolutaLo mismo en Windows, que numera los volúmenes con letras.
imagenes/logo.svgRelativaUna subcarpeta de la carpeta en la que estás ahora.
../compartido/guia.pdfRelativa.. sube un nivel; luego entra en compartido.

Dos convenciones que conviene tener claras: . significa «la carpeta actual» y .. significa «la carpeta superior». Y Windows separa con barra invertida \ mientras que Linux y macOS usan la barra normal /.

4.1. Extensión, formato y aplicación no son lo mismo

Tres cosas distintasEl formato es cómo están organizados los bytes dentro del archivo. La extensión es solo una pista escrita en el nombre. La aplicación es el programa que sabe interpretar ese formato. Cambiar .jpg por .pdf no convierte nada: solo cambia la etiqueta y consigue que el sistema abra el programa equivocado.

4.2. Nombrar archivos con criterio

Un nombre debe permitir encontrar el archivo dentro de seis meses. informe_2026-09-11_v2.pdf informa; nuevo definitivo bueno (1).pdf no. Conviene además evitar acentos, espacios y caracteres raros si el archivo va a viajar entre sistemas distintos, y usar fechas en formato AAAA-MM-DD, que ordena cronológicamente por sí solo.

Los metadatos también viajanMuchos archivos guardan información adicional que no se ve al abrirlos: quién los creó, con qué programa, cuándo y, en el caso de las fotos, con frecuencia las coordenadas exactas del lugar donde se tomaron. Antes de publicar o enviar un archivo conviene saber qué metadatos lleva dentro.

5. Usuarios y permisos

Aquí está la respuesta a la pregunta guía. Para que dos personas compartan un equipo sin pisarse hacen falta tres mecanismos:

  1. Identificación: cada persona tiene una cuenta y demuestra que es ella al iniciar sesión.
  2. Separación: cada cuenta tiene su propia carpeta personal y su propia configuración.
  3. Autorización: unos permisos determinan qué puede hacer cada cuenta sobre cada archivo.

Los permisos clásicos distinguen tres acciones —leer, escribir y ejecutar— y se asignan a usuarios y a grupos, que son conjuntos de usuarios con las mismas necesidades. Es mucho más manejable dar permiso al grupo «profesorado» que a cuarenta cuentas una por una.

Principio de mínimo privilegioCada cuenta debe tener exactamente los permisos que necesita para su trabajo, y ni uno más. Si alguien solo consulta una carpeta compartida, no debe poder modificarla. No es desconfianza: reduce el daño de un error y limita lo que puede hacer un atacante si consigue esa cuenta.
Por qué no se trabaja como administradorLa cuenta de administrador puede modificar el sistema entero. Si navegas y abres correo con ella, cualquier programa que ejecutes por error hereda ese poder. Por eso los sistemas actuales te hacen trabajar con una cuenta normal y piden confirmación explícita cuando algo necesita privilegios. Ese cuadro de diálogo molesto es una medida de seguridad, no un trámite.

6. Las interfaces: línea de comandos y gráfica

Interfaz de línea de comandosInterfaz gráfica (GUI)
Cómo se usaEscribiendo órdenes de texto.Señalando ventanas, iconos y menús.
AprendizajeHay que conocer los comandos.Se descubre explorando.
PrecisiónMuy alta: la orden dice exactamente qué hacer.Depende de las opciones que ofrezca el programa.
RepetibleSí: una orden se guarda, se comparte y se automatiza.Difícil: hay que repetir los clics.
Trabajo masivoRenombrar mil archivos es una línea.Renombrar mil archivos son mil operaciones.
Uso remotoFunciona con conexiones lentas.Necesita mucho más ancho de banda.

No compiten: conviven. La interfaz gráfica es mejor para explorar, comparar y trabajar con contenido visual; la línea de comandos es mejor para repetir, automatizar y administrar. Casi todos los administradores de sistemas usan las dos según la tarea.

🤔 Para pensar: una ventaja poco evidente de la línea de comandos es que la orden queda escrita. Si mañana alguien pregunta qué hiciste exactamente para arreglar un problema, puedes enseñar la línea. Con una interfaz gráfica tendrías que reconstruir de memoria una secuencia de clics. ¿Qué relación tiene esto con el método de diagnóstico del Tema 6?

7. Tipos de sistemas operativos

La misma máquina admite clasificaciones distintas según el criterio:

CriterioCategoríasEjemplo
Usuarios simultáneosMonousuario / multiusuarioUn móvil frente a un servidor con decenas de sesiones abiertas.
Tareas simultáneasMonotarea / multitareaUn microondas frente a cualquier ordenador actual.
Ámbito de usoEscritorio / servidor / móvil / embebidoWindows, Windows Server, Android, el sistema de un router.
Exigencia temporalDe propósito general / de tiempo realUn portátil frente al control de frenada de un coche.
Qué significa «tiempo real»Un sistema de tiempo real no es un sistema rápido: es un sistema que garantiza responder antes de un plazo determinado, siempre, sin excepciones. En el airbag de un coche, una respuesta correcta que llega veinte milisegundos tarde es una respuesta inútil. Un ordenador de escritorio es muy rápido de media, pero no garantiza nada: cualquier proceso puede retrasar a otro.

7.1. Los sistemas actuales

En equipos de escritorio predomina Windows, seguido de macOS y de las distintas distribuciones de GNU/Linux. En dispositivos móviles, Android e iOS se reparten prácticamente todo el mercado. En servidores y sistemas embebidos, Linux es dominante.

🐧 ¿Sabías que…? Los 500 supercomputadores más potentes del mundo funcionan con Linux, sin una sola excepción, y así ocurre de forma ininterrumpida desde 2017. El MareNostrum 5 del Tema 4 también. La razón es práctica: cuando cada instalación es única, tener el código fuente para adaptarlo deja de ser una cuestión ideológica y se convierte en un requisito técnico.
Cuidado con los porcentajes de cuotaLas cifras de reparto de sistemas operativos varían mucho según la fuente, porque casi todas se miden contando visitas a páginas web, no dispositivos. Eso deja fuera servidores, sistemas embebidos y equipos sin navegar. Son órdenes de magnitud útiles, no censos: úsalas con esa cautela y cita siempre de dónde salen y de cuándo.

8. Arranque múltiple, máquinas virtuales y contenedores

Nada obliga a usar un solo sistema operativo. Hay tres formas de convivir con varios:

TécnicaCómo funcionaCuándo conviene
Arranque múltipleVarios sistemas instalados en particiones distintas; el gestor de arranque del Tema 6 pregunta al encender.Cuando se necesita todo el rendimiento del equipo en cada sistema.
Máquina virtualUn programa simula un ordenador completo y dentro se instala otro sistema, que funciona en una ventana.Para probar, aprender o aislar algo sin tocar el equipo real.
ContenedorSe aísla una aplicación con lo que necesita, pero compartiendo el núcleo del sistema anfitrión.Para desplegar servicios de forma reproducible; muy usado en servidores.
💡 Una máquina virtual es la mejor herramienta para experimentar sin miedo: puedes romperla del todo y volver a empezar en un minuto. Además, muchas permiten guardar instantáneas del estado y regresar a ellas, lo que resulta utilísimo para probar una instalación o una configuración nueva.

9. Gestión básica de un equipo

Cuentas

Una cuenta por persona, con contraseña propia. La cuenta de administrador, solo para administrar. Revisar y retirar las cuentas que ya no se usan.

Actualizaciones

La mayoría de las actualizaciones del sistema corrigen fallos de seguridad ya conocidos y publicados. Retrasarlas no es prudencia: es dejar abierta una puerta que otros ya conocen.

Copias de seguridad

La regla 3-2-1 del Tema 7. Y una copia que nunca se ha probado a restaurar no cuenta como copia.

Espacio y rendimiento

Vigilar el espacio libre, revisar qué programas arrancan solos y mirar el uso de CPU, memoria y disco antes de diagnosticar «va lento».

Glosario del tema

Sistema operativo
Programa que administra los recursos del equipo y ofrece una forma cómoda y segura de usarlos.
Software de sistema
Software que crea las condiciones para que funcionen las aplicaciones, sin resolver tareas del usuario.
Núcleo
Parte central del sistema operativo, con privilegios máximos sobre procesos, memoria y dispositivos.
Proceso
Ejecución concreta de un programa, con su memoria, su estado y sus recursos.
Hilo
Secuencia de ejecución dentro de un proceso; varios hilos comparten su memoria.
Planificador
Componente que reparte el tiempo de CPU entre los procesos en ejecución.
Intérprete de comandos
Programa que recibe las órdenes del usuario y las traduce en peticiones al núcleo.
Sistema de archivos
Conjunto de reglas que organiza los datos del soporte en archivos y carpetas.
Ruta absoluta
Localización de un archivo desde la raíz del sistema o del volumen.
Ruta relativa
Localización a partir de la carpeta actual, usando . y ...
Permiso
Autorización para leer, escribir o ejecutar un archivo, asignada a usuarios o grupos.
Mínimo privilegio
Criterio que concede a cada cuenta solo los permisos imprescindibles.
Interfaz de línea de comandos
Interfaz textual en la que se escriben órdenes; repetible y automatizable.
Tiempo real
Sistema que garantiza responder antes de un plazo máximo determinado.
Máquina virtual
Ordenador simulado por software dentro de otro, con su propio sistema operativo.

Resumen esencial

  1. El software se organiza en capas: firmware, sistema operativo, bibliotecas y aplicaciones.
  2. El sistema operativo administra procesos, memoria, dispositivos, archivos y usuarios, y oculta los detalles del hardware.
  3. Un programa es código guardado; un proceso es una ejecución concreta con estado y recursos.
  4. Sus componentes son el núcleo, el intérprete de comandos y el sistema de archivos.
  5. Extensión, formato y aplicación son tres cosas distintas: renombrar un archivo no lo convierte.
  6. Compartir un equipo con seguridad exige identificación, separación y permisos, guiados por el mínimo privilegio.
  7. La línea de comandos y la interfaz gráfica no compiten: una es repetible y automatizable, la otra explorable.
  8. Un sistema de tiempo real no es rápido: garantiza responder antes de un plazo.
  9. Arranque múltiple, máquinas virtuales y contenedores permiten convivir con varios sistemas a la vez.
