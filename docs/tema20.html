Antes de empezar: ¿en qué momento un programa deja de caber en la cabeza, y qué se hace entonces?
Al terminar serás capaz de…
  • definir funciones con parámetros y valor de retorno, y llamarlas
  • distinguir variables locales y globales y explicar por qué importa
  • usar módulos de la biblioteca estándar como math y random
  • descomponer un programa en funciones con una responsabilidad cada una
  • separar el cálculo de la entrada y de la presentación

1. Por qué existen las funciones

El programa de estadísticas del Tema 18 tenía unas treinta líneas y ya costaba abarcarlo de un vistazo. Con cien líneas resulta imposible, y con mil no lo entiende ni quien lo escribió.

Aquí está la respuesta a la pregunta guíaUn programa deja de caber en la cabeza cuando hay que recordar demasiadas cosas a la vez. La solución no es ser más listo: es dividirlo en piezas que se puedan entender por separado. Una función bien hecha se puede usar sabiendo solo qué hace, sin necesidad de recordar cómo lo hace. Eso es lo que libera espacio mental.

Las funciones aportan cuatro cosas concretas:

Reutilización

Un cálculo escrito una vez se usa desde muchos sitios. Si hay que corregirlo, se corrige en un solo lugar.

Legibilidad

calcular_media(notas) se entiende al instante; las cinco líneas que hay dentro, no tanto.

Comprobación

Una función se puede probar aislada con distintos datos, sin ejecutar el programa entero.

División del trabajo

Varias personas pueden escribir funciones distintas si está claro qué recibe y qué devuelve cada una.

De hecho ya llevas todo el bloque usando funciones: print(), input(), len(), sum() y sorted() lo son. Ahora vas a escribir las tuyas.

2. Definir y llamar

Una función se define con def, un nombre, unos paréntesis y dos puntos; su contenido va sangrado, como los bloques del Tema 18.

def saludar():
    print("Hola, Ciencias de la Computación I")

# Definirla no la ejecuta. Hay que llamarla:
saludar()
saludar()
Hola, Ciencias de la Computación I
Hola, Ciencias de la Computación I
Definir no es ejecutarEl bloque def solo le dice a Python «recuerda este procedimiento con este nombre». No se ejecuta nada hasta que aparece la llamada, con los paréntesis. Un error frecuente al empezar es escribir una función perfecta y extrañarse de que el programa no haga nada: falta llamarla.

3.2. Devolver un resultado

La instrucción return termina la función y entrega un valor a quien la llamó:

def calcular_media(numeros):
    return sum(numeros) / len(numeros)

media = calcular_media([7, 4, 9, 5])
print(f"La media es {media:.2f}")
print(f"El doble de la media es {calcular_media([7, 4, 9, 5]) * 2:.2f}")
La media es 6.25
El doble de la media es 12.50
return no es printEs la confusión más importante de este tema. print() muestra algo en pantalla y no deja nada aprovechable; return entrega un valor al programa, que puede guardarlo, operarlo o volver a pasarlo a otra función. Una función que calcula debe devolver, no imprimir: si imprime, su resultado ya no sirve para nada más.
# Mal: el resultado se pierde, no se puede reutilizar
def media_mal(numeros):
    print(sum(numeros) / len(numeros))

resultado = media_mal([7, 4, 9, 5])
print(resultado)     # None: la función no devolvió nada
6.25
None

3.3. Varios parámetros y valores por defecto

def precio_final(base, iva=0.21, descuento=0):
    con_descuento = base * (1 - descuento)
    return con_descuento * (1 + iva)

print(round(precio_final(100), 2))
print(round(precio_final(100, descuento=0.10), 2))
print(round(precio_final(100, iva=0.10), 2))
121.0
108.9
110.0
💡 Los parámetros con valor por defecto hacen la función cómoda en el caso habitual y flexible en los demás. Y nombrar el argumento al llamarla —descuento=0.10— evita tener que recordar el orden y deja claro qué significa cada número.

4. Ámbito de las variables

Las variables creadas dentro de una función son locales: nacen al empezar la llamada y desaparecen al terminarla. Fuera no existen.

def calcular_area(base, altura):
    area = base * altura / 2     # 'area' es local
    return area

print(calcular_area(10, 4))
# print(area)   # NameError: 'area' no existe aquí fuera
20.0
El ámbito es una ventaja, no una molestiaQue las variables sean locales es justamente lo que permite entender una función por separado: puedes usar i o total dentro sin miedo a pisar nada del resto del programa. Es la encapsulación, y es lo que hace que una pieza sea de verdad independiente.
Evita depender de variables globalesUna función puede leer una variable definida fuera, y eso tienta a usarla en lugar de pasarla como parámetro. Es mala idea: la función deja de ser autónoma, no se puede probar sola y falla si se copia a otro programa. Todo lo que la función necesite, que entre por parámetros; todo lo que produzca, que salga por return. Las constantes en mayúsculas son la excepción razonable.

5. La biblioteca estándar: math y random

Python incluye centenares de funciones ya escritas, organizadas en módulos. Para usarlas basta con importarlos.

import math

print(math.sqrt(144))
print(round(math.pi, 4))
print(math.ceil(4.1), math.floor(4.9))
print(round(math.hypot(3, 4), 1))
12.0
3.1416
5 4
5.0
import random

random.seed(42)          # fija el azar para poder repetir la ejecución
print(random.randint(1, 6))
print(random.choice(["piedra", "papel", "tijera"]))

cartas = [1, 2, 3, 4, 5]
random.shuffle(cartas)
print(cartas)
💡 random.seed() parece un detalle menor y es muy útil: fija el punto de partida del azar, de modo que el programa produce siempre la misma secuencia. Sirve para poder repetir exactamente una ejecución mientras buscas un error, algo imposible si cada vez salen números distintos. Es un algoritmo probabilístico de los del Tema 16 convertido temporalmente en repetible.
Antes de programar algo, comprueba si ya existeLa biblioteca estándar de Python trae módulos para fechas, texto, matemáticas, azar, archivos, redes y mucho más. Reescribir una función que ya existe cuesta tiempo y casi siempre sale peor: la versión de la biblioteca está probada por millones de personas y contempla casos límite que tú no habrías previsto.

6. Descomponer un programa en funciones

La descomposición del Tema 16 se materializa aquí. La regla de oro:

Una función, una responsabilidadCada función debe hacer una cosa y su nombre debe decir cuál. Si al describir lo que hace necesitas la palabra «y» —«calcula la media y la muestra y guarda el resultado»—, casi seguro que son tres funciones.
SíntomaQué suele indicar
La función no cabe en la pantallaHace demasiadas cosas; hay partes que pueden salir.
Su nombre necesita un «y»Tiene más de una responsabilidad.
Recibe ocho parámetrosProbablemente esos datos deberían ir juntos en una estructura.
Hay código repetido en dos sitiosEse trozo repetido quiere ser una función.
Cuesta ponerle nombreTodavía no está claro qué hace exactamente.

7. Separar cálculo, entrada y presentación

Es la decisión de diseño más rentable que aprenderás este curso. Un programa tiene tres clases de trabajo, y conviene no mezclarlas:

Entrada

Obtener los datos: del usuario, de un archivo, de la red. Funciones con input().

Cálculo

Transformar esos datos en el resultado. Funciones puras: reciben, calculan y devuelven.

Presentación

Mostrar el resultado con formato. Funciones con print().

# Mal: todo mezclado. Imposible de probar sin teclear datos.
def procesar():
    n = int(input("Nota: "))
    if n >= 5:
        print("Aprobado")
    else:
        print("Suspenso")

# Bien: el cálculo está aislado y se puede comprobar solo.
def calificar(nota):
    return "Aprobado" if nota >= 5 else "Suspenso"

print(calificar(7))
print(calificar(3))
print(calificar(5))
Aprobado
Suspenso
Aprobado
Por qué esto importa tantoLa función calificar() se puede probar con veinte valores en un segundo, sin teclear nada. La versión mezclada exige ejecutar el programa y escribir a mano cada caso. Como verás en el Tema 21, separar el cálculo es lo que hace posible probar un programa; sin esa separación, comprobar cualquier cosa se vuelve tan lento que se deja de hacer.

8. Documentar y nombrar

8.1. Docstrings

Un docstring es una cadena de texto colocada como primera línea de la función. Explica qué hace, y Python la conserva de modo que se puede consultar con help().

def calcular_media(numeros):
    """Devuelve la media aritmética de una lista de números.

    Recibe una lista no vacía de int o float.
    Con una lista vacía provocaría un error de división por cero.
    """
    return sum(numeros) / len(numeros)

print(calcular_media.__doc__.splitlines()[0])
Devuelve la media aritmética de una lista de números.
💡 Un docstring útil dice qué recibe, qué devuelve y qué pasa en los casos raros. No repite el código: nadie necesita leer «suma y divide» si eso ya se ve. Y fíjate en que el ejemplo documenta explícitamente el caso de la lista vacía; documentar un límite conocido vale tanto como resolverlo.

9. Un programa completo, paso a paso

Reescribamos el programa de estadísticas del Tema 18, ahora con funciones. Se construye de forma incremental: cada función se escribe y se comprueba antes de pasar a la siguiente.

9.1. Las funciones de cálculo, probadas por separado

def calcular_media(notas):
    """Devuelve la media de una lista no vacía de notas."""
    return sum(notas) / len(notas)

def contar_aprobados(notas, minimo=5):
    """Devuelve cuántas notas alcanzan o superan el mínimo."""
    aprobados = 0
    for nota in notas:
        if nota >= minimo:
            aprobados += 1
    return aprobados

def valorar(media):
    """Devuelve una valoración cualitativa a partir de la media."""
    if media >= 7:
        return "resultados buenos"
    elif media >= 5:
        return "resultados suficientes"
    else:
        return "conviene revisar la unidad"

# Comprobación inmediata, sin teclear nada:
print(calcular_media([7, 4, 9, 6]))
print(contar_aprobados([7, 4, 9, 6]))
print(valorar(6.5))
6.5
3
resultados suficientes
💡 Observa aprobados += 1: es una forma abreviada de aprobados = aprobados + 1. Existen también -=, *= y /=, y son de uso muy común.

9.2. Las funciones de entrada y de salida

NOTA_MINIMA = 0
NOTA_MAXIMA = 10

def leer_nota(numero):
    """Pide una nota válida al usuario y la devuelve."""
    nota = -1
    while nota < NOTA_MINIMA or nota > NOTA_MAXIMA:
        nota = float(input(f"Nota {numero}: "))
        if nota < NOTA_MINIMA or nota > NOTA_MAXIMA:
            print(f"Debe estar entre {NOTA_MINIMA} y {NOTA_MAXIMA}.")
    return nota

def leer_notas(cantidad):
    """Devuelve una lista con las notas introducidas por el usuario."""
    notas = []
    for i in range(cantidad):
        notas.append(leer_nota(i + 1))
    return notas

def mostrar_informe(notas):
    """Muestra por pantalla las estadísticas de una lista de notas."""
    media = calcular_media(notas)
    aprobados = contar_aprobados(notas)
    porcentaje = aprobados / len(notas) * 100
    print()
    print(f"Notas introducidas: {len(notas)}")
    print(f"Media:              {media:.2f}")
    print(f"Aprobados:          {aprobados} ({porcentaje:.1f} %)")
    print(f"Valoración:         {valorar(media)}.")

9.3. El programa principal

cantidad = int(input("¿Cuántas notas? "))
notas = leer_notas(cantidad)
mostrar_informe(notas)
Tres líneas que se leen como una fraseEl programa principal ha quedado en tres líneas que cualquiera entiende sin bajar a los detalles: pregunta cuántas, léelas, muestra el informe. Toda la complejidad sigue ahí, pero ahora está repartida en piezas de cinco o seis líneas que se entienden y se comprueban por separado. Eso es la programación modular del Tema 9, y es la respuesta completa a la pregunta guía.
🤔 Para pensar: compara esta versión con la del Tema 18. Hacen exactamente lo mismo y esta es más larga en total. ¿Por qué merece la pena? Piensa en tres situaciones: cambiar el criterio de aprobado a 6, añadir la nota mínima al informe, y reutilizar el cálculo de la media en otro programa. ¿Cuánto trabajo costaría cada cosa en una versión y en la otra?

Glosario del tema

Función
Bloque de código con nombre propio que realiza una tarea y puede devolver un resultado.
def
Palabra clave que define una función; definirla no la ejecuta.
Llamada
Uso de una función escribiendo su nombre seguido de paréntesis.
Parámetro
Nombre que aparece en la definición y recibirá un valor.
Argumento
Valor concreto que se pasa a la función al llamarla.
return
Instrucción que termina la función y entrega un valor a quien la llamó.
Valor por defecto
Valor que toma un parámetro si no se indica al llamar.
Variable local
Variable creada dentro de una función, que solo existe durante su ejecución.
Encapsulación
Aislamiento del interior de una pieza respecto del resto del programa.
Módulo
Archivo de la biblioteca con funciones agrupadas, que se incorpora con import.
Biblioteca estándar
Conjunto de módulos que vienen incluidos con Python.
Docstring
Cadena de documentación colocada como primera línea de una función.
Una responsabilidad
Criterio según el cual cada función debe hacer una sola cosa.
Programación modular
Organización de un programa en piezas independientes y reutilizables.

Resumen esencial

  1. Un programa deja de caber en la cabeza cuando hay que recordar demasiado a la vez; las funciones reparten esa carga.
  2. Definir una función no la ejecuta: hace falta llamarla.
  3. return entrega un valor reutilizable; print() solo muestra y no deja nada.
  4. Las variables locales aíslan la función y permiten entenderla por separado.
  5. Todo lo que necesite una función entra por parámetros y todo lo que produzca sale por return.
  6. Antes de programar algo, comprueba si ya existe en la biblioteca estándar.
  7. Una función, una responsabilidad: si su nombre necesita un «y», son varias funciones.
  8. Separar cálculo, entrada y presentación es lo que hace posible probar un programa.
  9. Un docstring dice qué recibe, qué devuelve y qué ocurre en los casos raros.
