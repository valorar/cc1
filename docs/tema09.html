Antes de empezar: ¿por qué existen cientos de lenguajes de programación en lugar de uno solo que sirva para todo?
Al terminar serás capaz de…
  • situar un lenguaje en su nivel de abstracción y explicar qué gana y qué pierde
  • distinguir sintaxis y semántica, y relacionarlas con los tipos de error
  • explicar cómo se ejecuta un programa compilado, uno interpretado y uno sobre máquina virtual
  • reconocer los principales tipos de programación y qué problema resuelve cada uno
  • justificar la elección de un lenguaje para una tarea concreta

En el Tema 3 viste la historia de los lenguajes; en el Tema 8, las capas de software. Este tema cierra el Bloque C explicando cómo se le dan instrucciones a la máquina, y es el puente directo hacia el Bloque E, donde empezarás a programar en Python.

1. Niveles de abstracción: de la máquina a las personas

Un procesador solo entiende código máquina: secuencias de bits que interpreta como instrucciones. Programar así es posible y es lo que se hacía al principio, pero resulta lentísimo, ilegible y atado a un modelo concreto de procesador.

NivelQué esVentajaInconveniente
Código máquinaLos bits que ejecuta directamente la CPU.Control absoluto; no necesita traducción.Ilegible y válido solo para una arquitectura.
EnsambladorLos mismos bits, escritos con abreviaturas legibles: MOV, ADD, JMP.Legible por una persona, conservando el control.Sigue atado al procesador; una línea por instrucción.
Alto nivelLenguajes que expresan datos, decisiones y repeticiones sin gestionar el procesador: C, Python, Java.Legible, portable y mucho más rápido de escribir.Se delega el control de detalles a un traductor.
Concepto claveSubir de nivel de abstracción significa delegar decisiones. En ensamblador decides en qué registro va cada valor; en Python escribes total = a + b y no te preocupas de dónde vive nada. Ganas velocidad de desarrollo y legibilidad; pierdes control fino sobre la máquina. Elegir lenguaje es, sobre todo, elegir qué detalles quieres controlar y cuáles prefieres delegar.
⚙️ ¿Sabías que…? Una sola línea de un lenguaje de alto nivel puede convertirse en decenas de instrucciones máquina. Y hoy los traductores generan, en la mayoría de los casos, código más eficiente que el que escribiría a mano una persona experta, porque conocen al detalle el comportamiento del procesador. Programar en ensamblador se reserva para casos muy concretos: arranque de sistemas, controladores y rutinas críticas.

2. Sintaxis, semántica y errores

Todo lenguaje de programación tiene dos dimensiones, igual que una lengua natural:

Sintaxis

Las formas válidas: dónde van los paréntesis, los dos puntos, la sangría. Si no se cumple, el traductor no puede ni analizar el programa.

Semántica

Lo que cada construcción significa: qué hace exactamente un bucle o una asignación. Un programa puede ser correcto de forma y equivocado de sentido.

De esa distinción salen los dos grandes tipos de error con los que convivirás todo el curso:

Tipo de errorQué ocurreCuándo se detecta
De sintaxisEl texto no cumple las reglas del lenguaje.Antes de ejecutar: el traductor se niega y señala la línea.
De ejecuciónLa forma es correcta, pero al ejecutar ocurre algo imposible: dividir entre cero, abrir un archivo que no existe.Durante la ejecución, con un mensaje de error.
De lógicaEl programa se ejecuta sin quejarse y produce un resultado equivocado.Solo si alguien lo comprueba. Es el más peligroso de los tres.
💡 Un error de sintaxis es molesto pero inofensivo: el traductor te para y te dice dónde. Un error de lógica pasa desapercibido y puede sobrevivir años en un programa. Esa es la razón de que las pruebas y la depuración sean contenido propio del curso y no un apéndice.

3. Compiladores, intérpretes y máquinas virtuales

Entre el código que escribes y las instrucciones que ejecuta el procesador hace falta una traducción. Hay tres estrategias.

3.1. Compilar

Un compilador lee el programa entero, lo analiza y produce un archivo ejecutable en código máquina. La traducción se hace una sola vez; después el ejecutable se lanza directamente, sin intermediarios. Es la estrategia de C y C++.

3.2. Interpretar

Un intérprete es un programa que lee el código fuente y lo va ejecutando sobre la marcha, instrucción a instrucción. No se genera ningún ejecutable: hace falta tener el intérprete instalado para poder ejecutar el programa.

3.3. Máquinas virtuales y código intermedio

La estrategia intermedia, y hoy la más extendida: el código fuente se compila a un código intermedio (o bytecode) que no corresponde a ningún procesador real, y una máquina virtual instalada en cada equipo lo ejecuta. Así se compila una vez y se ejecuta en cualquier sistema que tenga esa máquina virtual. Es el modelo de Java y de C#.

CompiladoInterpretadoMáquina virtual
Velocidad de ejecuciónMáximaMenorIntermedia y buena en la práctica
PortabilidadHay que recompilar para cada sistemaAlta: basta con tener el intérpreteAlta: basta con tener la máquina virtual
Ciclo de trabajoEscribir, compilar, ejecutarEscribir y ejecutar; muy ágil para probarEscribir, compilar rápido, ejecutar
Se distribuye…Un ejecutable, sin el código fuenteEl código fuenteEl código intermedio
EjemplosC, C++, RustPython, JavaScriptJava, C#
La frontera es más borrosa de lo que pareceCasi ningún lenguaje actual es puramente una cosa u otra. Muchos intérpretes traducen el código a una forma intermedia antes de ejecutarlo, y varias máquinas virtuales compilan a código máquina durante la ejecución las partes que más se repiten, una técnica llamada compilación al vuelo. Compilado e interpretado describen mejor una forma de ejecutar que una propiedad fija del lenguaje.

4. Dónde encaja Python

Python, el lenguaje del Bloque E, se sitúa así:

CaracterísticaQué significa para ti
Alto nivelNo gestionas memoria ni registros; te concentras en el problema.
InterpretadoEscribes y ejecutas al momento, sin paso de compilación. Ideal para aprender y para probar ideas.
Propósito generalSirve para cálculo, web, datos, automatización o inteligencia artificial; no está atado a un dominio.
MultiparadigmaAdmite programación estructurada, modular y orientada a objetos: puedes usar el enfoque que convenga.
Legibilidad como prioridadSu sintaxis obliga a sangrar el código, de modo que la forma del programa refleja su estructura.
💡 Que Python sea «lento» comparado con C es cierto y casi siempre irrelevante. En la mayoría de los programas, el tiempo que se ahorra escribiéndolos vale mucho más que los milisegundos que se pierden ejecutándolos. Y cuando la velocidad importa de verdad, las partes críticas suelen estar escritas en C por debajo, aunque se usen desde Python.

5. Imperativa frente a declarativa

Los tipos de programación —o paradigmas— son formas distintas de plantear la solución. La primera división es la más profunda:

Imperativa

Se describe cómo hacerlo: una secuencia de pasos que van cambiando el estado hasta llegar al resultado. Es la forma en que programarás en el Bloque E.

Declarativa

Se describe qué se quiere obtener, y el sistema decide cómo conseguirlo. El programador especifica el resultado, no el procedimiento.

El ejemplo más claro es una consulta a una base de datos. En SQL se escribe algo parecido a «dame los alumnos de segundo ordenados por apellido»: no se dice cómo recorrer los datos, ni en qué orden, ni con qué método ordenar. El gestor decide la estrategia. Lo estudiarás en el Tema 12.

ImperativaDeclarativa
El programador indicaLa secuencia de pasos.El resultado deseado.
ControlTotal sobre el procedimiento.Se delega en el sistema.
EjemplosPython, C, JavaSQL, Prolog, HTML, hojas de cálculo
📊 ¿Sabías que…? Una hoja de cálculo es declarativa y casi nadie lo piensa. Al escribir =SUMA(A1:A10) no ordenas «recorre las celdas y ve acumulando»: declaras que esa celda vale la suma de ese rango, y el programa se ocupa de recalcularla cuando cambie cualquier dato. Millones de personas programan de forma declarativa a diario sin saber que están programando.

6. Estructurada, modular y orientada a objetos

Dentro del enfoque imperativo hay varias formas de organizar el código, y aparecieron históricamente como respuesta a un problema concreto: a medida que los programas crecen, se vuelven imposibles de entender.

6.1. Programación estructurada

En los años sesenta era normal usar saltos incondicionales para ir de un punto a otro del programa. El resultado era el llamado código espagueti: imposible de seguir. La programación estructurada demostró que todo programa puede escribirse con solo tres construcciones:

  • Secuencia: una instrucción después de otra.
  • Selección: elegir entre alternativas según una condición.
  • Iteración: repetir mientras se cumpla una condición.

Son exactamente las estructuras que aprenderás en el Tema 18. Al eliminar los saltos arbitrarios, el flujo del programa se puede seguir leyendo de arriba abajo.

6.2. Programación modular

El siguiente paso es dividir el programa en partes con nombre propio —funciones, procedimientos, módulos— que resuelven una tarea concreta y se pueden probar por separado. Cada módulo esconde sus detalles internos y ofrece una interfaz clara, de modo que quien lo usa no necesita saber cómo está hecho por dentro. Es el contenido del Tema 20.

6.3. Programación orientada a objetos

La modularidad separa el código en funciones, pero los datos siguen sueltos. La programación orientada a objetos reúne en una misma unidad, el objeto, los datos y las operaciones que actúan sobre ellos.

ConceptoQué esEjemplo
ClaseLa plantilla que define qué datos y qué operaciones tendrá un tipo de objeto.La clase Alumno.
ObjetoUn ejemplar concreto creado a partir de la clase, con sus propios valores.Un alumno concreto con su nombre y sus notas.
AtributoCada dato que guarda el objeto.Nombre, curso, notas.
MétodoCada operación que el objeto sabe hacer.Calcular su media.
Este curso no programa con objetosLa orientación a objetos aparece aquí como tipo de programación que hay que reconocer, porque el currículo lo pide y porque es el enfoque dominante en la industria. Programar con clases y objetos es contenido de Ciencias de la Computación II. En 1.º trabajarás con programación estructurada y modular, que es la base sobre la que se apoya todo lo demás.

7. Programación orientada a eventos

Los programas vistos hasta ahora siguen un guion: empiezan, hacen lo suyo y terminan. Pero una aplicación con ventanas no funciona así. No sabe qué va a pasar ni cuándo: el usuario puede pulsar un botón, mover el ratón, redimensionar la ventana o no hacer nada durante diez minutos.

En la programación orientada a eventos, el programa se organiza como un conjunto de manejadores: trozos de código asociados a un suceso concreto. El programa espera en un bucle, y cuando ocurre algo —un clic, la llegada de un dato por la red, el vencimiento de un temporizador— ejecuta el manejador correspondiente y vuelve a esperar.

El cambio de mentalidadEn un programa clásico, tú decides el orden de lo que ocurre. En uno orientado a eventos, el orden lo decide el mundo exterior y tú solo defines qué hacer en cada caso. Es el modelo de cualquier interfaz gráfica, de las páginas web interactivas y de las aplicaciones móviles.
🤔 Para pensar: estos enfoques no son excluyentes. Una aplicación móvil actual es orientada a eventos en su interfaz, orientada a objetos en su organización, estructurada dentro de cada método y usa consultas declarativas para acceder a sus datos. ¿Tiene sentido preguntar «de qué paradigma es» un programa real?

8. Cómo se elige un lenguaje

Ya puedes responder a la pregunta guía: existen cientos de lenguajes porque cada uno resuelve bien un tipo de problema y ninguno los resuelve todos.

CriterioPregunta que hay que hacerse
Dominio¿Es para web, cálculo, sistemas, móvil, datos? Cada campo tiene lenguajes asentados.
Rendimiento¿Importan los milisegundos, o importa más terminar antes de escribirlo?
Control¿Necesito gestionar memoria y hardware, o prefiero delegarlo?
Ecosistema¿Existen bibliotecas que ya resuelvan parte del problema? Suele pesar más que el lenguaje en sí.
Equipo¿Qué sabe usar y mantener la gente que trabajará en ello?
Ejecución¿Dónde tiene que funcionar? Un navegador, un servidor y un microcontrolador imponen cosas distintas.
LenguajeNivel y ejecuciónSe usa sobre todo para
CAlto nivel próximo a la máquina; compiladoSistemas operativos, controladores, sistemas embebidos.
PythonAlto nivel; interpretadoAutomatización, ciencia de datos, IA, web, enseñanza.
JavaAlto nivel; máquina virtualAplicaciones empresariales y Android.
JavaScriptAlto nivel; interpretado en el navegadorInteractividad en páginas web; también servidores.
SQLDeclarativo, de dominio específicoConsultar y modificar bases de datos.
Criterio claveLo que de verdad se transfiere de un lenguaje a otro no es la sintaxis, sino saber descomponer un problema, elegir estructuras de datos y comprobar que la solución funciona. Quien domina eso aprende un lenguaje nuevo en semanas. Por eso este curso enseña a programar usando Python, y no «enseña Python».

Ensamblador
Lenguaje de bajo nivel que representa las instrucciones máquina con abreviaturas legibles.
Lenguaje de alto nivel
Lenguaje próximo al razonamiento humano e independiente del procesador.
Sintaxis
Reglas que determinan qué construcciones son válidas en un lenguaje.
Semántica
Significado de cada construcción del lenguaje.
Compilador
Programa que traduce todo el código fuente a un ejecutable antes de la ejecución.
Intérprete
Programa que lee y ejecuta el código fuente instrucción a instrucción.
Código intermedio
Representación entre el código fuente y el código máquina, ejecutada por una máquina virtual.
Paradigma
Forma general de plantear la organización de un programa.
Programación imperativa
Enfoque que describe la secuencia de pasos que hay que ejecutar.
Programación declarativa
Enfoque que describe el resultado deseado y delega el procedimiento.
Programación estructurada

Programación modular
División del programa en partes con nombre propio que se pueden probar por separado.

Enfoque que reúne datos y operaciones en objetos creados a partir de clases.
Orientada a eventos
Enfoque en el que el programa responde a sucesos externos mediante manejadores.

Resumen esencial

  1. Subir de nivel de abstracción es delegar decisiones: se gana legibilidad y portabilidad, se pierde control fino.
  2. La sintaxis dice qué formas son válidas y la semántica qué significan; de ahí salen los errores de sintaxis, de ejecución y de lógica.
  3. El error de lógica es el más peligroso porque no se manifiesta solo: hay que comprobarlo.
  4. Compilar traduce una vez y produce un ejecutable; interpretar ejecuta sobre la marcha; la máquina virtual combina ambos con código intermedio.
  5. Python es de alto nivel, interpretado, de propósito general y multiparadigma, y prioriza la legibilidad.
  6. La programación imperativa describe cómo; la declarativa describe qué, como hacen SQL o una hoja de cálculo.
  7. Estructurada, modular y orientada a objetos son respuestas sucesivas al mismo problema: que los programas grandes se vuelven incomprensibles.
  8. En la programación orientada a eventos, el orden lo decide el mundo exterior y el programa solo define qué hacer en cada caso.
  9. Lo que se transfiere de un lenguaje a otro no es la sintaxis, sino saber descomponer, elegir estructuras y comprobar.
