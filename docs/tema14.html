Antes de empezar: cuando escribes una dirección y pulsas Intro, ¿qué ocurre exactamente hasta que la página aparece en tu pantalla?
Al terminar serás capaz de…
  • describir el intercambio entre cliente y servidor e interpretar las partes de una URL
  • separar estructura, presentación y comportamiento en HTML, CSS y JavaScript
  • escribir HTML semántico y aplicar estilos desde una hoja externa
  • explicar en qué consiste un diseño adaptable
  • organizar un sitio con rutas relativas y una navegación comprensible

1. Cómo funciona la Web: cliente, servidor, URL y HTTP

Toda la Web funciona sobre un intercambio muy simple: el cliente —tu navegador— pide algo y el servidor responde. Nada más. Lo que ocurre al pulsar Intro es esto:

1 — Resolución del nombre

El navegador pregunta al DNS qué dirección IP corresponde a ese nombre de dominio. Los nombres son para las personas; la red trabaja con números.

2 — Conexión y petición

El navegador conecta con ese servidor y le envía una petición HTTP: «dame este recurso».

3 — Respuesta

El servidor devuelve un código de estado y, si todo va bien, el contenido: normalmente un archivo HTML.

4 — Peticiones adicionales

Al leer el HTML, el navegador descubre que necesita hojas de estilo, imágenes y guiones, y hace una petición por cada uno.

5 — Representación

Con todas las piezas, el navegador construye y dibuja la página. Todo el proceso suele durar menos de un segundo.

1.1. Las partes de una URL

Una URL es la dirección completa de un recurso. Por ejemplo, https://valorar.github.io/cc1/tema14.html:

ParteEjemploQué indica
Esquemahttps://El protocolo. La s significa que la conexión va cifrada.
Dominiovalorar.github.ioQué servidor atiende la petición.
Ruta/cc1/tema14.htmlQué recurso concreto se pide dentro de ese servidor.
Parámetros?q=redesDatos adicionales para el servidor, tras la interrogación.
Fragmento#accesibilidadUn punto dentro de la página. No se envía al servidor: lo usa el navegador.

1.2. Códigos de estado

CódigoSignifica
200Correcto: aquí tienes el recurso.
301 / 302Redirección: el recurso está en otra dirección.
403Prohibido: existe, pero no tienes permiso.
404No encontrado: en el servidor no hay nada en esa ruta.
500Error del servidor: el fallo está en el otro extremo, no en tu equipo.
🐈 ¿Sabías que…? El famoso 404 no es un mensaje del navegador: es un código que envía el servidor, y cada sitio puede personalizar la página que lo acompaña. Prueba a escribir una dirección inventada dentro de este mismo sitio y verás la nuestra. Distinguir un 404 de un 500 ahorra mucho tiempo: el primero significa que te has equivocado de dirección, el segundo que el problema no es tuyo.
💡 HTTPS no es opcional. Cifra el intercambio para que nadie en el camino pueda leerlo ni alterarlo, y verifica que el servidor es quien dice ser. Los navegadores marcan como no seguras las páginas que aún usan HTTP, y hoy los certificados son gratuitos: no hay excusa para publicar sin él.

2. Los tres lenguajes de la Web

HTML — estructura

Marca qué es cada cosa: esto es un título, esto un párrafo, esto una lista, esto un enlace. Es el esqueleto y el significado.

CSS — presentación

Decide cómo se ve: colores, tipografías, tamaños, espaciado y disposición en la pantalla.

JavaScript — comportamiento

Añade qué ocurre al interactuar: validar un formulario, desplegar un menú, actualizar datos sin recargar.

Por qué se separanEs la misma idea que los estilos del Tema 11, llevada a la Web. Con la estructura separada de la presentación, se cambia el aspecto de un sitio entero editando un solo archivo, el contenido sigue teniendo sentido aunque falle el diseño, y un lector de pantalla o un buscador pueden entender la página aunque no la dibujen. Mezclarlas produce sitios imposibles de mantener.
💡 Este curso trabaja HTML y CSS. JavaScript se menciona por su función, pero programar la interactividad de una página no es contenido de 1.º: en el Bloque E programarás en Python.

3. HTML: la estructura y el significado

Un documento HTML se compone de etiquetas que envuelven el contenido y le dan sentido. La mayoría van por pares: una de apertura y otra de cierre.

EtiquetaQué marca
<h1> … <h6>Encabezados de seis niveles jerárquicos.
<p>Un párrafo.
<ul>, <ol>, <li>Listas sin ordenar, ordenadas y sus elementos.
<a href="…">Un enlace a otro recurso.
<img src="…" alt="…">Una imagen, con su descripción alternativa.
<table>, <tr>, <th>, <td>Tablas de datos, con celdas de encabezado y de contenido.

3.1. HTML semántico

Además existen etiquetas que describen el papel de cada zona de la página: <header>, <nav>, <main>, <section>, <article>, <aside> y <footer>. Usarlas se llama escribir HTML semántico, y no es un capricho de estilo: es lo que permite a un lector de pantalla ofrecer «saltar a la navegación» o «ir al contenido principal», y a un buscador entender qué parte de la página importa.

El error más extendidoUsar <div> para todo y simular los títulos con tamaño y negrita. Visualmente puede quedar idéntico, pero la página pierde toda su estructura: no se puede navegar por encabezados, los buscadores no distinguen jerarquía y el contenido deja de tener significado sin el CSS. Exactamente el mismo error que dar formato manual en lugar de aplicar estilos.

3.2. Encabezados y jerarquía

Un solo <h1> por página, que es su título. Debajo, <h2> para las secciones y <h3> para los apartados, sin saltarse niveles. El conjunto de encabezados debe leerse como un índice del contenido.

4. CSS: la presentación

Una regla CSS se compone de un selector, que indica a qué elementos se aplica, y un conjunto de propiedades con sus valores:

SelectorSelecciona
pTodos los párrafos.
.avisoTodos los elementos con la clase aviso.
#contenidoEl elemento con ese identificador único.
nav aLos enlaces que estén dentro de un elemento de navegación.

El CSS puede escribirse dentro de la propia etiqueta, dentro de la página o en un archivo externo enlazado. Solo la tercera opción es razonable en un sitio real: una hoja compartida por todas las páginas se edita una vez y el navegador la guarda en caché, de modo que el resto del sitio carga más rápido.

💡 Este mismo sitio funciona así: las catorce páginas comparten un único archivo estilos.css. Cambiar un color de la asignatura es editar una línea en un archivo, no en catorce.

5. Diseño adaptable

Una misma página se ve hoy en un móvil de 5 pulgadas, en un portátil y en un televisor. El diseño adaptable consiste en que el contenido se reorganice según el espacio disponible, en lugar de tener una versión distinta para cada dispositivo.

TécnicaEn qué consiste
Unidades relativasDefinir tamaños en proporción al espacio o al texto, no en píxeles fijos.
Imágenes flexiblesLimitar su anchura al contenedor para que nunca desborden.
Consultas de mediosAplicar reglas distintas según la anchura de la pantalla: por ejemplo, pasar de dos columnas a una.
Diseño móvil primeroDiseñar para la pantalla pequeña y añadir después lo que aproveche las grandes. Obliga a priorizar el contenido.
La prueba más sencillaAbre tu página en el ordenador y estrecha la ventana hasta el ancho de un móvil. Si aparece una barra de desplazamiento horizontal, el diseño no es adaptable: algún elemento tiene una anchura fija que no cabe. Es una comprobación de cinco segundos que detecta la mayoría de los problemas.

6. Editores de código y gestores de contenidos

EnfoqueCómo se trabajaCuándo conviene
Editor de códigoSe escriben los archivos HTML y CSS a mano.Sitios pequeños, aprendizaje y control total del resultado.
Generador de sitios estáticosSe escribe el contenido en texto y una herramienta genera las páginas.Sitios con muchas páginas de estructura repetida.
Gestor de contenidos (CMS)Se administra desde el navegador; el contenido vive en una base de datos.Sitios que actualizan varias personas sin saber programar.
Constructor visualSe arrastran bloques prediseñados.Resultados rápidos, a cambio de dependencia de la plataforma.
🌐 ¿Sabías que…? Esta web es un sitio estático: solo archivos HTML, una hoja de estilos y una imagen, alojados gratuitamente en GitHub Pages. No hay base de datos ni servidor de aplicaciones que mantener, no puede «caerse» por una sobrecarga y es imposible atacarla por la vía habitual, porque no hay ningún programa ejecutándose en el servidor. Para un sitio de contenido que cambia poco, lo estático suele ser la mejor decisión técnica, no la más pobre.

7. Organizar la información y la navegación

7.1. Estructura de archivos

Un sitio es una carpeta con archivos y subcarpetas. Tres convenciones importantes:

  • La página principal se llama index.html: es la que el servidor entrega cuando se pide la carpeta sin nombre de archivo.
  • Los recursos —hojas de estilo, imágenes, guiones— van en subcarpetas ordenadas, no sueltos junto a las páginas.
  • Los nombres de archivo, en minúsculas, sin espacios y sin acentos. Muchos servidores distinguen mayúsculas de minúsculas, y un enlace que funciona en tu equipo puede dar 404 al publicarlo.

7.2. Rutas relativas

Los enlaces internos deben usar rutas relativas, con la misma lógica que viste en el Tema 8: tema15.html para una página hermana, assets/estilos.css para bajar a una subcarpeta, ../index.html para subir un nivel. Así el sitio funciona igual en tu equipo que publicado, y se puede mover entero sin romper nada.

7.3. Navegación comprensible

PrincipioQué significa
OrientaciónDesde cualquier página, saber dónde estoy, qué hay alrededor y cómo volver.
CoherenciaEl menú está siempre en el mismo sitio y con los mismos nombres.
Enlaces descriptivosEl texto del enlace dice adónde lleva, sin depender del párrafo que lo rodea.
Jerarquía planaPocos niveles: enterrar contenido a cinco clics equivale a esconderlo.
Página de error útilUn 404 que ofrezca una salida hacia el índice, no un callejón sin salida.

8. Publicar: alojamiento, dominio y mantenimiento

Alojamiento

El servidor donde viven los archivos y que los sirve a quien los pida. Puede ser un servicio de pago, un alojamiento gratuito de páginas estáticas o un servidor propio.

Dominio

El nombre por el que se llega. Se alquila por años a un registrador. Los .es los gestiona Red.es.

Certificado

Lo que habilita HTTPS. Hoy la mayoría de los alojamientos lo incluyen y lo renuevan solos.

Mantenimiento

Actualizar el contenido, revisar enlaces rotos, mantener el software al día y conservar copias.

Publicar es hacer públicoTodo lo que subes queda accesible para cualquiera y puede quedar copiado en archivos y buscadores aunque después lo borres. Antes de publicar: comprueba que no incluyes datos personales de terceros, que tienes derecho a usar todas las imágenes y que no expones información de contacto que no quieres difundir. Un sitio publicado por error se retira, pero no se «desdifunde».

9. Accesibilidad y validación

9.1. Los cuatro principios

Las pautas internacionales de accesibilidad web, las WCAG del W3C, se organizan en cuatro principios. Un contenido debe ser:

PrincipioSignificaEjemplo concreto
PerceptibleSe puede percibir por algún sentido.Texto alternativo en imágenes; subtítulos en vídeo; contraste suficiente.
OperableSe puede manejar de distintas formas.Todo accesible con teclado; foco visible; sin límites de tiempo rígidos.
ComprensibleEl contenido y el funcionamiento se entienden.Idioma declarado; navegación coherente; errores explicados con claridad.
RobustoFunciona con distintas tecnologías, hoy y mañana.HTML válido y semántico que las tecnologías de apoyo puedan interpretar.

Las pautas se agrupan en tres niveles de exigencia: A, AA y AAA. El nivel de referencia habitual, y el que exige la ley, es el AA.

9.2. Qué obliga la normativa en España

NormaA quién obliga
Real Decreto 1112/2018Sitios web y aplicaciones móviles del sector público. Exige la norma europea EN 301 549, equivalente a WCAG 2.1 nivel AA, y publicar una declaración de accesibilidad.
Ley 11/2023Desde el 28 de junio de 2025 extiende requisitos de accesibilidad a determinados productos y servicios del sector privado, como el comercio electrónico. Transpone la Ley Europea de Accesibilidad y deja fuera a las microempresas.
Un cambio importanteLa accesibilidad web ha dejado de ser una recomendación de buenas prácticas o una obligación solo para las administraciones. Desde 2025 es también una obligación legal para muchas empresas privadas en España. Y, más allá de la ley: hablamos de un porcentaje muy alto de la población que en algún momento de su vida encuentra barreras —por discapacidad permanente, por una lesión temporal o simplemente por la edad—.

9.3. Comprobar antes de publicar

  • Validador de HTML del W3C: detecta etiquetas mal cerradas y errores de estructura.
  • Herramientas de accesibilidad como WAVE o las integradas en el navegador: señalan imágenes sin texto alternativo, contrastes insuficientes y encabezados mal jerarquizados.
  • Prueba de teclado: recorre toda la página con el tabulador. Si no puedes llegar a algo o no ves dónde está el foco, no es operable.
  • Prueba de anchura: estrecha la ventana hasta el tamaño de un móvil.
  • Prueba sin estilos: desactiva el CSS. Si el contenido sigue leyéndose en orden lógico, la estructura es correcta.
🤔 Para pensar: repasa los requisitos de accesibilidad de documentos del Tema 11 y los de este tema. Son prácticamente los mismos: encabezados reales, texto alternativo, contraste, no depender del color, enlaces descriptivos. ¿Por qué crees que las buenas prácticas coinciden en soportes tan distintos?

Resumen esencial

  1. La Web es un intercambio de peticiones y respuestas entre cliente y servidor, previa resolución del nombre por DNS.
  2. Una URL tiene partes con función propia, y el código de estado dice si el problema es tuyo o del servidor.
  3. HTML da estructura, CSS presentación y JavaScript comportamiento: separarlos es lo que hace mantenible un sitio.
  4. El HTML semántico permite navegar por la página y que su contenido tenga sentido sin el diseño.
  5. Un diseño adaptable reorganiza el contenido; la prueba es estrechar la ventana y no encontrar barra horizontal.
  6. Un sitio estático es a menudo la mejor decisión técnica para contenido que cambia poco.
  7. Rutas relativas, nombres en minúsculas y una página index.html: así el sitio funciona igual en local que publicado.
  8. Publicar es hacer público, y lo publicado puede quedar copiado aunque después se borre.
  9. La accesibilidad se organiza en cuatro principios y, desde 2025, obliga en España también a muchas empresas privadas.
